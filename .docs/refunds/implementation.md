# 账单退款实现与验收范围

## 本轮确认规则

- 支出详情进入退款页；首笔默认全额，已有部分退款时默认剩余可退金额。
- “实际金额与账单金额不同”开关默认关闭，打开后填写本次实际退款金额。
- 实际入账账户、时间沿用原支出，不重新选择；原支出保留不改金额。
- 支持多次退款，单次必须为正，累计不超过原金额。按币种最小单位比较，不用浮点累加作上限判断。
- 同一退款请求重复提交只返回既有记录；本地数据库事务内重读金额、账户、权限及退款累计。
- 退款与“退款收入”将使用同一组实际退款记录；不是两次入账。本轮未改洞察统计页 UI，也未改变预算扣减。

## 数据与余额

退款复用一条 `income` 类型交易，设置 `excludeFromStats=true` 与 `excludeFromBudget=true`。账户余额沿用现有流水模型自然加回一次，不修改账户 `initialBalance`。普通月度收入及首页日收入不混入退款；账户流水中的“入账”仍可能含退款，这是现金流口径。

退款的原账单关联使用版本化 `syncId`：

```
beecount-refund-v1:<base64url(originalSyncId), 无 padding>:<request UUID>
```

编码只包含稳定标识，不嵌入金额、备注或姓名。解析需规范编码与 UUID 校验，退款不能再关联退款。旧账单缺 syncId 时，在同一事务中补齐；同步 outbox 写失败则整笔回滚。沿用现有交易表和 schemaVersion，不引入新依赖或代码生成。

退款的币种、原账户、日期及隐含汇率快照沿用原支出；历史 NULL 折算快照保持 NULL，不使用今日汇率制造新的快照。缺账户、账户币种不一致、估值类账户及无编辑权限不允许退款。隐藏但仍存在的支付账户可以沿用。

有退款时，原支出的金额、日期、账户、币种、跨账本移动及删除被保护。备注、分类、标签等非金额信息仍可在详情修改。退款不能通过普通账单编辑或复制；删除退款记录会撤销那一笔账户回流，然后可重新登记。批量删除原账单必须同时包含其全部退款，禁止制造悬空关联。

## 同步、备份与兼容性

- JSON 账本备份和现有同步 payload 已有 syncId，故不增加未知的服务端字段；serializer / apply / JSON import 保持退款标识与排除标记。
- 补充客户端 fake-provider 冷插入／重复回放用例与 JSON 导出导入用例。**本轮未运行这些用例，未连接真实服务端验证。**
- 非 UUID 的版本化 syncId 是否被某个云端部署接受、真实设备间恢复、旧版本客户端展示和编辑行为，仍须后续集成验收；不能仅凭客户端代码声称兼容所有服务端。
- 不保证旧版本客户端理解退款标签与编辑保护。CSV/第三方导出不作为本轮完整退款关系恢复格式，建议使用 JSON 备份。
- 本地事务可阻止本设备并发超退；多设备离线同时退款没有服务端总额约束，无法保证全局强一致。同步后累计/账户不一致会阻止继续退款，需核对重复或冲突记录。
- 共享账本沿用项目现有成员资产归属规则，不擅自将加入的共享账本计入个人净资产。

## 待执行验收

1. 原支出100，默认退100；原支出仍100，原账户加100一次，重复保存不再加。
2. 依次退30、20、剩余50；拒绝第4笔、负数、0、超额及超币种精度金额。
3. 在打开的退款页面期间原账单或剩余可退金额变化，保存必须提示重新打开。
4. 无账户、账户删除／错币种、只读账本、同步 outbox 失败均不产生错误回流；隐藏原账户仍可沿用。
5. 原支出与退款互相跳转，原支出显示累计与多条退款；原金额编辑、移动、删除及普通编辑/复制退款被阻止。
6. 删除退款只撤销这一笔回流；删除所有退款后可再次编辑原支出。
7. JPY/KWD、外币快照、信用卡、共享镜像账户以及 JSON 恢复和云端重复回放。
8. iOS 小屏、大字体、暗色及键盘弹出布局；取消不写账。
