# 支付截图作为账单附件（第3项）

## 使用

1. “接收并确认账单”的“支付截屏”接截图变量；金额、分类、账户等仍来自用户传入和本地分类规则。
2. 确认菜单说明有没有截图；有图时明确“1张，仅保存到账单详情图片，不用于 AI”。
3. 将输出的**整份账单确认结果**连接到“保存账单”，不只连接文本字段，不增加第三个保存动作。
4. 保存后在该账单详情的“图片”中查看。保存凭证带附件数量，截图缺失或变化不静默保存无图账单。

## 本轮改动与既有行为

原有 Dart 保存器已能在同一数据库事务中写入账单、附件关系、提交凭证和同步 outbox，文件按内容哈希复用；本轮复用该机制，不再额外创建第二条账单或单独加减余额。

本轮补上第一动作确认后的 run-local 图片字节快照，避免第二动作仅持有已过期输入文件 URL。外部文件读取在 security scope 内进行，确认结果只带 IntentFile、张数和图片指纹，不将 base64 塞入普通账单 JSON。指纹不写日志。截图内容不会交给识别、OCR、分类或任何 AI 调用。

保存动作校验图片存在性和指纹，沿用确认时冻结的原图／压缩偏好。只有保存动作才产生正式图片附件。取消时不校验无关图片、不写附件；原图格式或压缩由既有附件开关决定。图片上限40MB，单笔变量账单保存1张截图。

正式图片文件、transaction_attachments 和详情页使用同一应用附件目录和读取接口。新附件显示来源名 payment-screenshot。事务中附件关联失败则账单、标签、凭证回滚；重复保存同一确认结果不重复记账和插图。若已收到入账回执但附件数量凭证不完整，提示用户先在 App 核对，不自动重记。

## 验证范围

补充原生的截图不进入 AI、丢图／改图拒绝、输入文件失效后的快照、取消以及缺附件回执用例；补充 Dart 单笔图片关系、余额不重复、关联失败回滚以及详情“图片”数量用例。仅静态复核，**没有运行原生测试、Flutter测试、analyzer、编译、Actions或真机操作**。

Apple IntentFile 文档核对了 data/fileURL 构造器和外部 URL 的 security-scoped 访问要求；系统是否在特定 iOS 版本完整保留 transient entity 中的 IntentFile，仍须新版真机验收。旧快捷指令若未连接整份确认结果，请在新版本重新选择对应动作参数。没有承诺此代码已解决一切系统跨动作序列化问题。
