# 系统输入记账：完整单笔与逐笔拆分（待统一编译）

## 状态与安全

本轮保留完整单笔并新增逐笔拆分路径，**确认保存会真实写入账单，不是 Build 19 的只显示结果**。
请先用单独测试账本/小额示例验收；运行中不读写当前草稿之外的账单，不自动重跑 AI。
未确认的当前笔、取消或系统输入时停止快捷指令，不会进入当前笔保存动作。
**逐笔拆分之前已经成功保存的笔不撤销**，剩余金额不会自动记入。停止不代表整次没有账单。

- 新系统输入路径的支出菜单新增“拆分并逐笔保存”，每笔独立确认、独立真实入账。
  取消只停止后续，不撤销已保存笔；不再沿用旧模板的最终统一保存设计。
  旧五入口/旧模板的批量拆分代码仍保留以免破坏旧指令，**不等于已经改成新逐笔模式**。
  要用新行为必须使用本目录的新动作组合。收入与转账保持单笔，详情页不改。
- 备注、金额、时间不使用 AppIntent requestValue 或内部 OpensIntent 交接。
  系统“请求输入”读取当前内容作默认答案，完成后回传给 App 恢复同一菜单。
- 单笔菜单包含账本、类型、金额、分类、账户、时间、备注、标签、支出不计预算；转账另有转入账户。
  标签支持多选、清空、返回不修改。金额按币种最小单位校验，不静默舍入超精度输入。
- 切换账本保留备注等修改；引用不适用时清除后重新选择。币种不同时明确确认并重新填写金额，不自动换算。
- 保存复用现有实时校验、请求 ID 去重与事务；本轮未重写数据库和同步。
  成功提示仅代表本机入账，云端同步状态请看 App；结果不明时不要另起请求重记。

## 手填分类匹配（本地执行，不调用 AI）

手填支出、收入，以及旧“自定义支出/收入账单”入口使用同一套本地匹配：
显式分类优先；分类留空且有线索时按个人规则优先级、再按内置关键词匹配。
个人规则沿用启用状态、账本限制、收支类型、包含/完全匹配和失效目标检查。
没有命中就保持未分类，不能随意挑第一个分类。转账不套支出/收入分类。

“开始单笔记账”新增可选的“商户（手填分类线索）”“原始全文（手填分类线索）”，
旧自定义支出/收入也有对应参数。可把外部 AI 整理出的字段直接连入，
不会发送到 App 内 AI、不写账单，不会把线索拼进或覆盖原备注。
只填备注时只具备备注与内置文本匹配能力；没有商户/全文就不伪造对应证据。

规则只在最开始生成手填草稿时执行一次。进入编辑后，改备注不重新套规则，
不会覆盖用户手动选择/清除的分类。已选分类最终仍须通过实时有效性校验。
模板没有硬编码这些可选字段，按需展开首动作接变量即可，无需每次手动复制。

## 新 App 动作

1. **开始单笔记账（系统输入）**：选择来源（图片 AI、文字 AI、手填支出/收入/转账），只产生草稿。
   图片连接截屏/照片；文字连接 OCR/文字，不要误选已有“AI识别草稿（测试，不记账）”。
   标签、不计预算可预设。图片模式会将识别副本发送给 App 配置的视觉服务；文字模式不发送原图。
2. **继续单笔确认（系统输入）**：显示菜单直到需要系统输入或用户最终确认/取消，只读草稿，不入账。
3. **保存已确认单笔账单**：只接受整笔的最终确认结果，提交恰好一条记录；不能接拆分确认步骤。
4. **保存拆分当前笔（逐笔入账）**：接受拆分当前笔确认结果，保存一条并返回新的进度步骤。
   结果未知返回可重试步骤，不扣余额、不另起请求。此动作后必须覆盖“单笔步骤”变量。

每一步输出的“单笔编辑步骤”是本次运行的临时实体，不是全局当前账单、数据库草稿或剪贴板。
可以在变量属性里选取：步骤状态、输入提示、输入类型、当前内容、当前数字、当前时间、结果说明、完整状态。
传给继续/保存的参数必须使用**完整实体变量**，不要只选“完整状态”字符串。
状态值还包括 split-confirmed / split-next / split-retry / split-ended，不要翻译这些值。
下面第一轮的手搭内容需要同时增加“逐笔状态补丁”才支持拆分，不能只更新 IPA 而不改指令。

## 手动搭建（无需签名模板）

先保留你已经验证成功的 Build 19 指令，新建一条“完整单笔测试”。
不再手工给每一个分类/标签写分支；App 负责完整菜单，快捷指令只承担三个输入类型分支。

### A. 循环外的四步

1. 添加“选择照片”（或截屏），只选一张。
2. 添加“开始单笔记账（系统输入）”：来源选“图片 AI”，图片接上一步；文字留空。
   如需文字模式，来源改“文字 AI”，文字接 OCR/文字，图片留空。
   首次验收也可用“手填支出”：金额填 0.01、备注填测试文字、指定测试账本与有效账户。
3. 添加“设定变量”，名字手填 **单笔步骤**，输入选第 2 步的完整结果，不选属性。
4. 添加“继续单笔确认（系统输入）”：上一步骤选变量 **单笔步骤**，已提供输入关闭，三个结果留空。
   紧接再添加“设定变量”，将 **单笔步骤** 覆盖为第 4 步完整输出。

首次运行在第 4 步显示完整菜单。点备注/金额/时间时它返回 input，交给下方循环处理；
选分类、标签、不计预算等时 App 菜单内部更新，直到需要输入或最终确认/取消才返回。

### B. 添加“重复 1000 次”，里面先处理最终状态

添加系统“如果”，左侧选择 **单笔步骤**，点变量属性选 **步骤状态**，条件“是”，右侧手填 `confirmed`。
在这个“如果”的成立分支内放：
- “保存已确认单笔账单”：最终确认步骤选 **单笔步骤**（完整变量）。
- 如要保存截图，附带图片明确连接循环外的原图；留空就不保存附件。文字/OCR 不可当图片。
- “停止快捷指令”。如系统仅有“停止并输出”，输出选保存动作的结果。
结束这个“如果”，不要把保存放在重复的末尾或无条件执行。

### C. 再判断是否需要输入

仍在重复里面，再添加一个“如果”：**单笔步骤 → 步骤状态** 是 `input`。
在成立分支内，根据 **单笔步骤 → 输入类型** 分成三种情况：

| 条件 | 请求输入类型 | 提示 | 默认答案 | 继续动作中填写 |
| --- | --- | --- | --- | --- |
| 是 `number` | 数字 | 单笔步骤→输入提示 | 单笔步骤→当前数字 | 数字结果=这次数字请求输入的输出 |
| 否则，如果是 `date` | 日期与时间 | 单笔步骤→输入提示 | 单笔步骤→当前时间 | 日期结果=这次日期请求输入的输出 |
| 其余 | 文本，多行可开 | 单笔步骤→输入提示 | 单笔步骤→当前内容 | 文字结果=这次文本请求输入的输出 |

**每一个输入分支**中，在“请求输入”后都放：
1. “继续单笔确认（系统输入）”：上一步骤=变量 **单笔步骤**，**已提供输入开启**；
   只连接表格对应的一个结果，另外两种结果留空。
2. “设定变量”：把 **单笔步骤** 覆盖为这个继续动作的完整输出。

不要给继续动作的字段设置“每次询问”，也不要使用旧“确认AI草稿”动作。
文本清空并点完成代表空备注，已提供输入必须开启；取消系统输入会停止，不会当作清空。
数字不用转成文字，日期不必手打 ISO；新动作会在内部统一序列化并校验。

在步骤状态是 input 的“否则”分支内放“停止快捷指令”，处理 cancelled/异常状态，绝不能落入保存。
所有“结束如果”在“结束重复”之前。达到 1000 次后只显示“当前笔和剩余金额未自动保存，先前已保存笔保留”并停止，不能自动提交或重跑 AI。

```text
选择照片/截屏
开始单笔记账（系统输入）
设定 单笔步骤 = 开始动作输出
继续单笔确认（已提供输入：关闭）
设定 单笔步骤 = 继续动作输出
重复 1000 次
    如果 单笔步骤.步骤状态 是 confirmed
        保存已确认单笔账单（完整单笔步骤，可连接原图）
        停止快捷指令
    结束如果
    如果 单笔步骤.步骤状态 是 input
        如果 单笔步骤.输入类型 是 number
            请求数字（默认：单笔步骤.当前数字）
            继续单笔确认（已提供输入：开启；数字结果：刚才的输入）
            设定 单笔步骤 = 这个继续动作输出
        否则
            如果 单笔步骤.输入类型 是 date
                请求日期与时间（默认：单笔步骤.当前时间）
                继续单笔确认（已提供输入：开启；日期结果：刚才的输入）
                设定 单笔步骤 = 这个继续动作输出
            否则
                请求文本（默认：单笔步骤.当前内容）
                继续单笔确认（已提供输入：开启；文字结果：刚才的输入）
                设定 单笔步骤 = 这个继续动作输出
            结束如果
        结束如果
    否则
        停止快捷指令
    结束如果
结束重复
显示达到上限，当前笔/剩余未自动保存，已保存笔保留；停止
```

## 逐笔状态补丁（模板文件已包含，手搭需要补）

在重复内部按以下顺序处理，不要把拆分确认结果传给普通单笔保存动作：

1. 状态是 `confirmed`：普通“保存已确认单笔账单”→停止，与单笔流程相同。
2. 状态是 `split-confirmed`：调用“保存拆分当前笔（逐笔入账）”，当前确认步骤接完整变量；
   可选附图也在这里明确连接。输出**覆盖单笔步骤**，不要停止，让下面判断新状态。
3. 状态是 `split-ended`：显示 **单笔步骤→结果说明**，然后停止。
4. 状态是 `cancelled`：停止（整笔尚未保存）。
5. 状态是 `input`：沿用数字/日期/文字三分支，系统输入完成→继续单笔确认（已提供输入开启）→覆盖步骤。
6. 其他状态（正常是 `split-next` / `split-retry`）：继续单笔确认（已提供输入关闭，三种结果留空）→覆盖步骤。
   这个动作会显示“继续下一笔／最后一笔／结束”或“同请求重试／结束并查询”，不会再识别。

在第 2 步保存后不要无条件执行“停止”或把旧确认步骤再次接入下一次保存。
每次使用最新的“单笔步骤”命名变量，输入默认答案也从最新步骤取属性。

## 逐笔拆分的实际操作

- 从未保存支出菜单点“拆分并逐笔保存”。原整笔不先入账；开始拆分就锁定原总额、账本、币种、付款账户和支出类型。
- 当前笔初始金额为剩余未记总额，继承进入拆分前的备注/分类/多标签/预算/时间。
  修改金额、备注等字段仍走系统输入，默认答案带当前笔最新值。
- 点“确认保存此笔”才保存一条；成功回执更新已记笔数、金额和剩余余额。
- 还有余额时可“继续拆下一笔”“剩余作为最后一笔编辑”“结束拆分”。
  新笔继承上一笔已保存字段作编辑初值，金额改为余额；这不代表自动保存，必须核对。
  选择最后一笔时，最终确认金额必须恰好等于余额。
- 原 300 元，保存 80 后显示剩余 220，保存 150 后剩余 70，再确认 70 后结束。
  中途结束会保留已保存的 80/150，不生成 300 的原账单，也不自动生成剩余 70。
- 当前笔超过余额/零/负数/小数位不符时拒绝，保留原值。每个会话最多 100 笔，达到上限不自动补记。
- 不提供“删除已保存明细”或回头改写已入账笔；那属于 App 的账单编辑。
  系统输入取消可能立即终止整个指令，无法保证一定显示总结，但先前已保存笔仍保留。

### 保存失败、超时和重复点击

- 每个会话/序号的请求 ID 固定；查询和保存均校验同一内容摘要（含明确选择的附件）。
- 失败或结果未知返回 `split-retry`，余额不推进，也不允许跳过当前笔直接新增。
  “重试保存当前笔”复用相同请求，若之前已保存就读取回执，不再插入账单。
- “结束并稍后查询”会提示当前笔可能已保存及请求 ID；请查询/检查账单后再处理，不能把原总额整笔再记。
- 已成功回执旁的最小进度元数据与当前账单、附件、回执同一事务保存；不保存未确认草稿或备注。
  仅新的本地表需要 schema v35 迁移，首次安装新版本后执行；不引入依赖、不删除原账单。
- 防止已拆分后用旧整笔确认再次入账；也防止原账单已整笔保存后再拆分同一请求。
  旧步骤或分支保存不能跳序号、改总额/账户/币种或超出当前已持久化余额。
- “不保存未确认草稿”意味着整个快捷指令结束后不承诺恢复编辑；本地成功进度用于防重和凭证核对，不是跨设备恢复服务。
  多设备独立重新识别会产生新请求，仍需要用户避免重复记同一账单。

## 未签名模板源码

同目录提供 image / text / expense / income / transfer 五份 `.unsigned.shortcut`。
图片模板自带“选择照片”，文字模板自带一次“请求输入”供粘贴文字；可自行换成前置截屏/OCR。
默认不附图，避免未经选择保存原截图。手填模板从首动作展开预设，缺字段在菜单核对。

模板 plist 序列化不是 Apple 公共 API，属性绑定、枚举来源和导入兼容性仍需真机检查。
**未签名文件不能承诺直接导入**。若重签更改 App 的 Bundle ID，需要重新生成/改绑 App 动作。
只在授权的 macOS/云端环境生成、签名；不要求飞牛安装任何工具。

```sh
python3 scripts/build-single-billing-templates.py --bundle-id com.tntlikely.beecount --output /tmp/single-billing
shortcuts sign --mode anyone --input /tmp/single-billing/image.unsigned.shortcut --output /tmp/single-billing/image.shortcut
```

签名工具与 Apple 服务可用性未验证，不会自行安装工具、申请证书或索取密钥。

## 验收清单（未运行，待统一编译后手机验收）

- 整笔先取消一次，确认没有新增账单；开始/继续动作均不得提交。
- 300 拆 80/150/70：每确认一笔检查 App 立即新增一条；前两笔后结束应只保留 80/150。
- 当前笔备注/金额连续修改、最后一笔超出或不足余额、零/负数/超精度错误。
- 保存回执丢失重试不重复记录、不重复扣余额；已提交请求内容改变不能当成同笔成功。
- 关闭 App/输入取消/保存失败时已提交部分保留，当前未知笔提示查询，不自动记剩余。
- v34→v35 升级保留原账单和旧回执，新进度表只在成功保存时创建行；事务失败不能留下扣额。
- 备注原文预填、增删、空备注、连续修改；金额原值、小数/超额校验后保留旧值。
- 修改备注→分类→金额→时间→标签→预算，前面修改不能丢失；日期默认应为账单当前时间。
- 标签预设多项不截断，增删/清空/返回不修改正确；支出预算标记保存后与菜单一致。
- 类型切换到收入或转账，不计预算为 false；转账必须不同账户，分类按类型重新校验。
- 账本切换后失效引用提示重选，币种不自动换算；取消账本币种切换不能破坏原草稿。
- 最终确认只写一条，真实金额/备注/标签/时间/账户与菜单一致；附件只按选择保存。
- 同一确认步骤重试沿用请求 ID；结果不明应查询，不要重新开始生成新请求 ID。
- 编辑期间杀掉 App/停止快捷指令、系统输入取消，不应自动保存；整个快捷指令结束不承诺恢复草稿。
