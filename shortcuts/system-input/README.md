# 系统“询问输入”组合快捷指令（源码模板）

状态：**未签名、未导入验证**。本目录的模板不是已验证可导入的成品；App 编译状态不能作为模板可用的证据。

普通「文字记账」不使用本目录的循环：接入文字/OCR 文本后直接显示确认菜单。旧的模板开关值不再让普通入口只返回草稿。文字模板改用隐藏的「文字记账草稿（模板专用）」动作；已经手搭的旧模板需要改首动作，不要把普通「文字记账」当作草稿动作。空文字请求系统参数输入；缺金额或账户先显示待核对菜单，这不代表备注/金额运行中输入故障已经解决。

## 使用效果

五个入口先只生成本次草稿，接着由“继续账单确认（模板）”显示菜单。点击备注、普通金额或拆分明细金额后，动作返回输入请求，系统“询问输入”用 `input.currentValue` 预填。完成后继续编辑同一笔；取消系统输入会终止快捷指令，不入账。删除全部备注后完成代表清空（须目标真机验证系统空响应行为）。

- `image`：图片记账；输入为图片，可从前置截屏动作/共享表单连接。
- `text`：文字记账；输入为文字，可接前置“从图像提取文本”的输出。
- `expense` / `income` / `transfer`：手填三个入口；在首个 App 动作展开参数填值或接变量，不调用 AI。
- 图片与手填模板首动作的 **系统询问输入模板模式 = 开启**；文字模板使用独立隐藏草稿动作，无此开关。只有完整模板才使用后续步骤；普通文字入口不要接这个循环。
- 备注和金额不再使用 App 内的 `requestValue`；标签、预算、分类、账户等菜单仍由 App 提供。
- 确认前只在快捷指令变量中传递草稿/步骤，不写持久化恢复草稿。AI 只在首步调用。后续通过重放已完成的菜单与输入恢复嵌套编辑位置，历史菜单不会再弹。
- 最终验证重新读取有效引用，保存复用原有原子事务及同请求 ID 防重复。

## 附带图片与预设

首步的附带图片在模板模式中**不会自动传到最后保存**。要保存截图，必须将同一截图变量连接到末尾“保存已确认账单（模板）”的“附带图片”；留空不保存。不要误把文字 OCR 输出当作图片。可给保存动作接截图，同时把 OCR 文字接首步文字动作，两者独立。

五份模板不主动截屏、不访问相册。你可在模板最前放“截屏”并把其变量接到图片入口、最后保存动作；或保留已有前置快捷指令步骤。账本、标签、预算等仍在首步展开参数预设。

## 模板生成和签名

仓库提供五份 `.unsigned.shortcut` XML 源码和标准库生成器。这些是配置源文件，不是已签名下载成品。plist 的动作序列化不是 Apple 公共 API，导入时的动作识别、变量绑定、系统版本适配仍须实测。

仅在用户授权的工作站运行（**不要在飞牛上安装或构建**）：

```sh
python3 scripts/build-shortcut-input-templates.py --bundle-id com.tntlikely.beecount --output /tmp/beecount-shortcuts
```

默认 bundle ID 仅为模板默认值。若 IPA 重签更改 Bundle ID，需要传入实际 Bundle ID 重新生成。模板的 AppIntent 标识也需在新版 App 安装后核实。`--team-id` 可传入签名后的 Team ID；默认占位不是本项目签名证据。

在已安装 Shortcuts CLI 的 macOS 上按系统帮助核对并签名，例如：

```sh
shortcuts sign --mode anyone --input /tmp/beecount-shortcuts/expense.unsigned.shortcut --output /tmp/beecount-shortcuts/expense.shortcut
```

其他四份同样处理。将签名后的文件导入 iPhone，再检查首次动作、模板模式、输入变量、最后附图变量。当前环境没有执行生成落盘、签名、导入、编译或真机测试；本次只在内存中做 plist 结构与引用检查。不能保证未签名源文件在设备上可直接打开。

## 手动搭建的等价步骤（供签名/导入无法使用时核对）

1. 图片/手填入口开启模板模式，文字改用「文字记账草稿（模板专用）」，输出存为变量 `账单步骤`。
2. 继续账单确认（模板）：上一步结果=`账单步骤`、已提供输入=关闭；输出覆盖 `账单步骤`。
3. 重复（模板设 1000 次上限，不会自动保存）：
   - 从 `账单步骤` 取得字典，读取 `status`。
   - `confirmed`：保存已确认账单（模板），传完整 `账单步骤`，可接附图；停止快捷指令。
   - `input`：读取 `input.prompt`、`input.currentValue`、`input.inputType`；按 number/text 调用系统“询问输入”，默认答案=`currentValue`。
   - 继续账单确认（模板）：上一步结果仍为完整 `账单步骤`、输入结果=询问输入结果、已提供输入=开启；输出覆盖 `账单步骤`，继续循环。
   - `cancelled` 或未知状态：停止，不调用保存。
4. 达到循环上限：显示未入账，停止。不要在循环末尾无条件保存。

## 待验收

- 五入口点备注直接弹系统输入、原备注预填、完成回原菜单；空输入、取消。
- 普通金额和 300 拆 80/150/70；修改已存在明细的金额上限为原总额减其他明细；超额/零/负数/精度错误保留旧值。
- 拆分中修改备注、分类、标签、预算后跨输入仍保留；首次取消明细保留整笔。
- 连续编辑、账本与收支类型切换、缺金额、多个候选；确认前无正式交易，确认后只保存一次。
- 输入期间 App 进程被系统终止，模板后续动作仍能从变量恢复；整个快捷指令终止后不承诺恢复。
- 更新/删除引用后最终校验拒绝失效值；附件同图拆分与保存幂等。

注意：步骤变量含本次账单内容，不要导出真实运行数据/日志，不要把识别或编辑结果写进模板静态内容。测试使用示例数据。
