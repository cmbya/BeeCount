# iOS 运行时预填隔离测试（Build 18）

## 范围与限制

仅新增可搜索的 **输入预填测试（不记账）** 动作，不改现有五个记账入口。
使用固定示例备注 `广东电网｜生活缴费`、金额 `12.34`，不调用 AI、Flutter
记账桥接或账单数据库，不发起任何账单提交，也不主动打开 App。
本测试不代表正式记账、拆分或预算功能已经修复。

要验证的假设：在同一个 `perform()` 中，先将当前草稿值赋给动作自己的可选
`@Parameter`，再显式调用该参数的 `requestValue`，系统是否将当前值放入
**可编辑输入框正文**。参数当前值可写、可以显式请求输入是官方 API；
当前值能否在实际 iOS/Shortcuts 宿主正确预填，必须由真机验证。

不使用 `OpensIntent` 内部交接、不抛 `needsValueError` 重启整个动作、
不要求用户建立额外循环或编辑动作。参数可选且禁止自动连接输入，避免运行前
必填参数解析干扰实验。结束后返回仅供查看的测试文字，不保存修改。

## 手机操作

1. 自行签名并安装此版 IPA；在快捷指令中新建一个指令。
2. 在蜜蜂记账的动作中搜索 **输入预填测试（不记账）**，只添加此动作。
   不接截图、不设置 AI、不设置动作参数、不加其他辅助动作。
3. 运行后看到备注、金额、结束测试三个菜单项。
4. 点备注，观察原文是否已经在**输入框正文**中，而不是仅出现在提示标题。
   在原文后加几个字并完成，菜单应显示修改后的备注。
5. 再点备注，观察输入框是否变成上次修改后的内容；删除部分文字后完成。
6. 将备注全部清空并完成，记录系统是接受空内容、阻止提交还是退出。
   如果成功返回菜单，应显示 `备注：（空）`；再次打开不能自动恢复示例原文。
7. 点金额，观察输入框是否带 `12.34`、键盘是否适合输入小数；改为 `56.78`
   并完成。再次进入应带 `56.78`，而非第一次的示例金额。
8. 点“结束测试（不保存）”，应收到最终测试内容，账单不应新增。
9. 另行运行一次，分别在备注和金额输入框取消，记录是回菜单、停止指令还是报错。
   系统取消可能直接终止本次动作；本测试不承诺跨取消保留会话。
10. 每次新运行都应恢复固定示例值，不能继承上次的修改。

反馈请提供 iOS 版本、卡在哪一步、输入框有没有原值，以及必要的错误截图。
测试只用示例数据，无须提供真实账单、账户信息或敏感日志。

## 验证边界

- 新增的原生回归用例只验证草稿当前值传递、连续修改、空备注和取消透传。
  它们不模拟或证明系统输入框 UI。
- 按用户要求，使用 IPA-only 工作流编译，不运行完整测试、lint、模拟器检查或
  发布 Release。新增测试本次也不执行。
- 云端编译成功只证明可以生成未签名 IPA；预填、键盘、连续交互和取消结果均待手机验证。
- 日志仅包含固定阶段和数字错误码，不记录备注正文、金额或错误描述。
