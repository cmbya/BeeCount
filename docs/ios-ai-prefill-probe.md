# Build 19：AI 草稿 → 快捷指令变量 → 预填确认（测试版）

## 本版边界

仅新增两个 App 动作，不修改原有五个记账入口或 Build 18 手动参数探针。
不接账单保存，也不测试正式拆分、标签或预算功能；这些能力没有被删除。
本版只验证单笔 AI 草稿能否在**第二个动作运行前**通过 Shortcuts 变量绑定到
备注、金额参数，并让菜单、首次编辑及连续编辑的内容保持一致。

AI 沿用 App 内配置：图片发送到已配置的视觉服务，文字仅发送到文字服务。
会读取当前账本和配置，不调用账单 commit，不保存测试草稿或修改结果。
图片识别沿用现有临时图片处理流程；不生成永久账单附件。

## 为什么是两个动作

Build 18 真机结果：在同一个 perform 中赋值后请求输入，没有预填；运行前参数
绑定有值时，首次和后续编辑均可预填。因此本版让第一个动作返回临时草稿实体，
由系统先解析第二个动作的备注、金额变量，再进入 perform。
仅把整个草稿传到第二个动作后在函数内部拆字段，不算这个实验，不能替代标量绑定。

## 新建快捷指令（只需配置一次）

两个 App 动作可以放在**同一条**快捷指令里，按顺序执行，无须分别运行。

### 第一个动作：AI识别草稿（测试，不记账）

- 图片测试：在前面放“截屏”或“选择照片”，把结果连接到此动作的“图片”。
  “文字”留空。
- 文字测试：将记账文字或“从图像中提取文本”的结果连接到“文字”。“图片”留空。
- 只能连接其中一种输入；账本留空使用 App 当前账本，也可显式选择。
- 返回值类型为 **AI 测试草稿**，可从变量里选取“备注”“金额”“币种”等属性。

### 第二个动作：确认AI草稿（测试，不保存）

展开动作，配置三个参数：

| 参数 | 选择的变量 |
| --- | --- |
| AI 草稿 | 上一个动作的完整“AI 测试草稿”结果，不选属性 |
| 备注 | 再选同一结果变量，点击变量，在属性中选择“备注” |
| 金额 | 再选同一结果变量，点击变量，在属性中选择“金额” |

如果系统已自动连接了“AI 草稿”，保留它。备注和金额仍须分别连接相应属性，
不能留空、手填固定值或把完整草稿当字符串填进去。配置一次后，每次识别都会
自动把本次 AI 值传入，不需要手动复制。测试菜单参数保持留空。

## 手机上检查

1. 用包含单笔明确金额的账单图片或测试文字运行。
2. 菜单中的备注、金额必须来自 AI，不能仍为“广东电网／12.34”写死的示例。
3. 点备注：AI 原文应在可编辑框正文中；增删后完成，再进入应是修改后的内容。
4. 点金额：应带识别金额；改成另一金额后完成，再进入应是最新金额。
5. 重复编辑备注、金额交替操作；可另行试备注清空和输入取消。
6. 选择“结束测试（不保存）”，查看最终文字；不会创建账单。
7. 再运行另一张账单，初值须来自新的识别结果，不能沿用上次修改。

如果提示“连接备注／金额”或“与草稿不一致”，检查两项是否选到了同一个
草稿结果的对应属性。本测试不会在参数缺失时偷偷退回运行中赋值的失败路径。
识别结果多笔、金额缺失或币种受阻会明确报错，不静默取第一笔或填零。

## 验证范围

- 新增原生回归用例覆盖字段解包、币种精度、输入校验、仅识别不提交及连续编辑状态。
- 按用户要求仅在 GitHub Actions 编译未签名 IPA，不跑完整测试或新用例、不发布 Release。
- 编译成功不代表系统变量属性选择、预填或 AI 识别已真机通过。
- 原账单保存、拆分等问题仍属后续任务；此次结束只返回普通测试文字，不能当提交载荷。
- 只反馈 iOS 版本、测试步骤和必要截图，不提供 API 密钥或真实账户敏感信息。

## Apple API

- [TransientAppEntity](https://developer.apple.com/documentation/appintents/transientappentity)：临时值通过属性暴露给 App Intents，无需草稿数据库查询。
- [EntityProperty](https://developer.apple.com/documentation/appintents/entityproperty)：向 Shortcuts 暴露可选取的属性。
- [IntentParameter.requestValue](https://developer.apple.com/documentation/appintents/intentparameter/requestvalue(_:)-592nd)：在当前动作中请求输入。
