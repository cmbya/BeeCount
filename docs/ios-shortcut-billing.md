# iOS 变量确认记账（个人 fork）

## 最新结构：第一步接收并确认，第二步只保存

同一条快捷指令中连续放两个动作：

**接收并确认账单 → 保存账单**

- **接收并确认账单**：直接接收你的变量，立即显示现有逐行确认菜单。金额、备注点击输入框；账本、分类、账户继续从 App 读取真实选项，标签仍点击轮换。点「确认提交」只输出最终确认结果，不写账单。
- **保存账单**：连接上一动作的整份「账单确认结果」，只重新校验并保存，不再弹编辑菜单或请求输入。取消结果不保存；未确认草稿不能当成确认结果。

不是新做全字段输入表单，不要求三个动作、循环、字典判断、外部“请求输入”分支或第三个保存步骤。不调用 AI，不增加拆分或不计收入。

## 第一步参数顺序

| 顺序 | 参数 | 变量与规则 |
|---|---|---|
| 1 | 金额 | 十进制文字；系统数字变量可转换为文字。按账本精度校验，不静默舍入 |
| 2 | 类型 | 支出／收入／转账，也接受 expense／income／transfer；留空按支出 |
| 3 | 账本 | App 账本对象；留空使用当前账本 |
| 4 | 分类 | 名称文字，支持只写二级分类名；也可传完整路径 |
| 5 | 标签 | 单个已有标签名称文字 |
| 6 | 账户 | 支出／收入的 App 账户对象 |
| 7 | 转出账户 | 转账的 App 账户对象 |
| 8 | 转入账户 | 转账的 App 账户对象，不能与转出账户相同 |
| 9 | 时间 | 传入 Date 变量，不擅自替换成当前时间 |
| 10 | 备注 | 实际文本原样保留，不保存变量名称或额外原始文本 |
| 11 | 不计预算（是／否） | 文字「是」排除预算，「否」计入；留空为否，仅支出有效 |
| 12 | 原始文本 | 分类线索，不调用 AI，不自动拼进备注 |
| 13 | 支付截屏 | 可选附件，随确认结果传给第二步保存，不识别 |

金额／备注编辑直接使用**第一步接收这些变量的 amount／note 参数**，不再用第二步额外的隐藏编辑槽。金额用十进制文本输入保留币种精度；这意味着数字专用键盘不作承诺。备注支持修改，系统允许完成空输入时表示清空。动态默认答案和输入框预填仍由宿主系统决定，不作为本版修复保证。

## 保持不变的选择交互

- **分类**：变量写「食品」时，唯一匹配后选中子分类「餐饮/食品」自己的 ID；父类拥有子类时不作为保存目标。重名或不存在显示待选择，不随意选第一个、不自动新建。
- **分类留空**：按备注／原始文本匹配启用的个人规则，然后内置关键词。不调用 AI。显式分类无效不被规则覆盖；改备注或手选分类后不重新套规则。
- **账本、分类、账户、转出／转入账户**：仍读取 App 数据，点击列表选择，不改成手填框。分类按一级分组再选二级，允许未分类。
- **标签**：仍读取 App 标签，点击个人 → 家庭 → 个人轮换，不做多选。无标签显示无；传入无效或重名标签先选择纠正。
- **类型、不计预算**：沿用现有文字选项，不改成输入框。转账不显示分类和预算，收入不显示预算。
- **时间**：使用传入值，可点击修改／补齐；金额、必需账户或时间缺失时先显示待补齐菜单，不能直接保存。
- **账本切换**：保留仍有效的修改，失效引用重新选择；币种或精度改变要明确确认并重新填写金额，不自动换算。

## 快捷指令如何连接

1. 添加 **接收并确认账单**，展开连接上述变量。分类示例「食品」，标签示例「个人」，不计预算示例「是」。
2. 添加 **保存账单**，「账单确认结果」连接上一步的**整体确认结果**。不要切换成「确认状态」或「确认内容」文字属性。
3. 运行第一步看到确认菜单，修改后点「确认提交」。第一步输出最终账单，快捷指令自动进入第二步保存，无 App 二次确认。
4. 点「取消提交」时输出无提交内容的取消结果，第二步不做任何读写。输入被宿主直接终止时也不能进入保存步骤。

旧「准备账单 → 确认并记账」的连接不能原样当作新结构已配置成功：第二动作现在只接已确认的结果，参数类型已变。新包安装后应检查两张动作卡及第二步的整体输出连接，不需要重搭循环或测试模板。现有 Release Build 23 尚不包含这次结构变更。

## 确认和保存的边界

第一步可读 App 选项、分类规则并执行只读校验，但不提交、不永久保存截图，不创建磁盘草稿或全局当前账单。所有点击修改更新同一草稿，最后确认才生成一条带固定 request ID、最终字段和附件设置的确认结果。

第二步没有编辑回调，不能回到第一步重新生成数据。它重新验证账本币种、精度及分类／标签／账户引用，使用确认结果内最终金额、备注、标签、预算等保存一条。确认后引用失效明确报错，不静默换分类、账户或金额。

截图文件随确认结果传递，原图保存设置在第一步确认时固定；第二步编码后与账单、标签、附件关联和请求凭证一起原子提交。重试同一结果沿用同一个 request ID 和最终内容；改变 App 原图设置不应改变原确认结果的附件内容。瞬态实体跨动作的截图传递仍需真机验证。

保存失败或结果不明时不弹新的编辑／重试菜单，明确提示在 App 核对最近提交凭证及实际账单。若查询已存在该 ID 的凭证，仍以同一最终 payload 再提交，交给存储层校验内容摘要；不把同 ID 的任意凭证直接当作成功。人工重试只沿用原确认结果重跑保存，不要重新运行第一步生成新 ID 重记。

成功只代表本机入账，云端同步请在 App 查看。数据库版本不变，历史账单、规则、预算、标签、已有拆分会话和其他 App 页面不删除或重构。
