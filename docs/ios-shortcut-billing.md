# iOS 快捷确认记账（个人 fork）

按个人需求新增：识别只返回草稿，在系统菜单核对、编辑或手动拆分，最终确认一次才保存正式交易，App 不要求第二次确认。

## 安装配置

1. 在本仓库 [Releases](https://github.com/cmbya/BeeCount/releases) 下载 iOS 快捷记账预发布版的 **BeeCount-shortcut-unsigned.ipa**。IPA 未签名，需自行签名安装，不能直接点开安装。上游商店版本不包含此 fork 的改动。本次修复提交使用 [skip ci]，未编译或运行测试。后续普通代码 push 仍会触发核心测试和 iOS 打包并行运行；打包完成先上传 IPA，测试与打包均通过后才自动发布预发布版。
2. 先启动 App，创建个人账本、同币种付款账户、支出分类和家庭/个人等标签。预算沿用现有总预算和分类预算。
3. 在智能记账设置进入 **iOS 快捷确认记账**，设置默认标签及预算标记，并管理个人分类规则。新动作默认使用 App 当前账本，也可在动作中指定账本；账户按内容识别，无法唯一匹配时必须选择，不使用旧默认账户。
4. 在现有 AI 服务配置中设置文字、视觉能力，复用项目已有智谱及 OpenAI 兼容服务。图片模式需要视觉模型，文字模式需要文字模型。不要把密钥写到快捷指令、JSON 或仓库。

支持个人账本中的支出、收入和转账；收入与转账为单笔，支出可以拆分。同组同账户，不支持共享账本、跨币种转账或混合账户拆分。币种自动跟随账本，不增加货币选择菜单。金额用对应币种最小单位整数计算：人民币 12.30 为 1230，日元 123 为 123，KWD 1.234 为 1234。

## 推荐快捷指令：两个完整入口

- **图片：截取屏幕 → BeeCount「图片记账」**，截图连接图片参数。
- **文字：截取屏幕 → 从图像提取文本 → BeeCount「文字记账」**，提取结果连接文字参数；也可传入普通文字。

两个动作均自动调用 App 内已配置的 AI，先判断收入/支出，再预填金额、分类、账户、时间和备注。无需先选择收入或支出、填写账单字段，或手工组合 JSON、草稿和提交动作。

分类顺序为个人规则、内置关键词、AI 推荐；AI 分类 ID 必须属于有效的对应收支分类。名称重名时不随意选第一个。账户按已有名称、银行和尾号线索唯一匹配；无法识别或有多个候选时弹出选择，不回退旧默认账户。无法识别时间时预填当前时间，确认菜单按设备本地时区展示。

动作可选预设账本、标签、清空标签及支出不计预算。账本留空使用 App 当前账本（冷启动读取已保存的当前账本），无效时明确提示，不静默选第一个。标签留空沿用 App 默认。确认菜单点击标签按 App 顺序轮换单个标签，无完成/清空子菜单。预算点击直接反转计入/不计入；收入不显示预算项。

运行后菜单按金额、分类、账户、时间、备注、标签、支出预算标记逐行展示当前值，点击修改，最后确认提交或取消。支出可拆分，所有明细最后一起入账，不回 App 二次确认。

图片动作固定调用视觉 AI，本地 OCR 仅补充分类规则和账户匹配线索，不自动切换文字模型；本地取字失败不阻止视觉识别，但提示核对规则结果。文字动作只向文字 AI 发送输入文本，不附原图。AI 服务商收到图片或文字均可能产生费用；不在快捷指令配置密钥。识别失败可主动人工填写或取消，不自动入账。

旧“识别并确认记账”及草稿辅助动作保留标识供已有快捷指令兼容，不作为主要入口。自定义支出/收入/转账重新作为手填动作展示，和图片、文字记账并存。手填动作不调用 AI；需要识别 OCR 时应使用文字记账，不把 OCR 原文误接到自定义支出的金额或备注来代替识别。

原生识别等待上限仍为 300 秒，iOS 可能更早结束后台任务，不保证固定时长。识别超时与提交结果未知分开处理。

汇总中可改金额、账户、日期时间和明细。每笔可改金额、分类、备注、单个轮换标签及是否计入预算。分类包含父级路径。备注可编辑、追加、清空重填、保存空备注或取消修改，保存采用最终编辑值。

汇总还可切换账本、收支类型。切换不同币种账本时不自动换算，需要重新填写金额并重建单笔草稿；切换类型会重新选择对应分类，拆分草稿须明确同意合并。收入选择收款账户、收入分类，不展示预算选项；转账选择不同的转出和转入账户，不展示分类与预算选项，复用原项目的一条 transfer 记录及虚拟转账分类，不产生支出。任何类型都支持标签和备注。

提交前会重新验证最新引用，错误时返回编辑菜单，可通过“刷新有效选项”重新读取分类、账户和标签。校验成功后才发送最终保存请求，保存时在事务内再次校验。

点击「拆分或新增明细」后，以逐笔明细替换原整笔草稿。每笔完成显示剩余，可新增、编辑、删除。合计不等于原付款、非正金额或未选分类时不能提交。所有明细一次提交，全部成功或全部回滚；取消或最终确认前中断不会产生部分交易。中断草稿不恢复。

## 独立动作与参数

下表为旧组合的兼容接口，不是日常配置步骤；新建快捷指令请使用上面的图片记账或文字记账。

| 动作 | 用途 |
|---|---|
| 获取快捷记账选项 | 当前有效账本、账户、分类、标签、默认配置和金额精度 JSON |
| 图片生成记账草稿 | 只识别图片，返回草稿，不保存 |
| 文字生成记账草稿 | 接收 OCR 文字，不接收原图 |
| 确认编辑记账草稿 | 系统菜单编辑，返回已确认 JSON，不保存 |
| 提交已确认账单 | 接收确认 JSON，原子入账 |
| 查询快捷记账结果 | 按请求 ID 查询，留空查本机最近一次提交 |

独立组合：**截屏 → 从图像提取文本 → 文字生成记账草稿 → 确认编辑记账草稿 → 提交已确认账单 → 显示结果**。前一动作文本输出接入后一动作 JSON 输入。获取选项动作可以指定 expense、income、transfer 类型，默认 expense。

默认配置 JSON 可省略。例如（ID 仅示例，必须先从获取选项动作取得真实有效 ID）：

    {"ledgerId":1,"accountId":2,"mode":"text","tagIds":[3,4],"excludeFromBudget":false}

tagIds 空数组表示清空，省略表示使用 App 默认；预算 false 表示明确计入预算。人工编辑优先于默认及 AI。提交前再次校验所有引用，失效时报错，不静默更换。

## 个人分类规则

App 内支持新增、编辑、停用、删除及数值优先级，越大越优先，同优先级按规则 ID 稳定排序。可匹配商户、备注、OCR 原文，支持包含/完全匹配，可限定账本。原文规则使用文字输入或图片本地 OCR 结果；图片取字失败时需人工核对。

顺序：**本次人工选择 > 启用的个人规则 > 内置分类匹配 > AI 建议 > 待选择**。规则必须指向有效收支分类，删除目标分类后不会写入失效引用。规则与默认配置仅在本机。

收入也可创建对应规则：目标分类列表标明收入/支出，规则自动限定为目标分类所属类型，不将支出规则应用到收入。转账不匹配分类规则。

## 结果和异常恢复

成功返回 committed、requestId、transactionIds、count、totalAmountMinor、currency、minorDigits。syncStatus=pending 表示只确认了本机保存，未确认远端同步；查看 App 同步状态，无需重记。

同一 requestId 和相同内容重复提交返回原交易 ID，不重复扣款；同 ID 改内容返回 REQUEST_CONFLICT。保存后删除原交易，再重试旧 ID 也不会重新创建。重新识别会生成新 ID，不能用重新截图代替超时后的查询。

| 结果/错误 | 处理 |
|---|---|
| AI_UNAVAILABLE / RECOGNITION_FAILED | 检查模型能力和网络，可人工填写；识别失败不入账 |
| INVALID_REFERENCE | 账本/账户/分类/标签失效，重新获取选项并纠正 |
| INVALID_AMOUNT / INVALID_REQUEST | 检查正金额、合计、日期时间和最终确认 |
| COMMIT_FAILED | 全部回滚，使用原 ID、原内容重试 |
| RESULT_UNKNOWN / 提交后关闭界面 | 可能已完成，先按原 ID 查询，不换 ID 重记 |
| REQUEST_CONFLICT | 原 ID 已对应其他内容，查询并核对原交易 |
| not_found | 本机尚未查到，不代表证明已撤销；保留原确认 JSON 时用同 ID 原内容安全重试 |

设置页可查看并复制最近 20 条提交结果。凭证、拆分分组、规则为本机元数据；正式交易和标签沿用已有同步路径。不新增元数据云同步/导出协议，不能假定普通业务备份恢复、换机后旧请求仍防重复；跨设备也不保证同一截图只记一次。备份恢复后先核对正式账目。

数据库 33 升至 34，新增三张本机表，不改旧交易结构。正常完成或失败会清理本次临时图片，进程被结束后后续图片识别会清理超过一小时的本功能临时图片。不保存中断草稿，不把识别请求和服务商响应写入普通 App 日志。

## 五入口可选附带图片（源码变更，未编译）

图片记账、文字记账、自定义支出、收入、转账均在展开的字段卡片中增加“附带图片”，可以连接快捷指令的截屏变量。它与图片 AI 的识别输入分离：留空不保存附件；图片记账想保留识别图，需把同一个截图变量也连接到附带图片。文字动作的附件不进入文字 AI 请求，手填动作不会因此调用 AI。

显式传入附件后，最终确认才按 App“附件保存原图”设置处理并保存，不受“自动添加附件”开关控制。取消不创建永久图片或关联。拆分每条明细关联同图，共用一份内容哈希命名文件。数据行、标签、附件关联、提交凭证在同一事务内保存；失败回滚并尝试清除本次新建且无引用的文件，复用文件不删。进程突然终止可能留下无引用文件，沿用现有孤立附件清理机制。

附件字节摘要纳入提交幂等；同请求同附件只保存一次，同请求换图拒绝。失败不能伪报记账成功。附件沿用原有存储、展示和同步路径，远端同步成功仍需另行验证。单图最大 40 MB；本次不编译、不运行新增回归测试、不发布。
