# iOS 快捷确认记账（个人 fork）

## 当前范围：只保留两个入口

- **图片记账**：截取屏幕 → 蜜蜂记账「图片记账」，把截图连接到「图片」。
- **文字记账**：截取屏幕 → 从图像提取文本 → 蜜蜂记账「文字记账」，把提取结果连接到「文字」；也可连接普通文字。

已撤下预填测试、AI 草稿测试、自定义支出／收入／转账、单笔步骤、逐笔拆分步骤及旧的选项／草稿／确认／保存／查询辅助动作；对应两套未签名模板、生成脚本和测试操作说明一并移除。不再提供模板模式开关，也不要求手工搭建变量循环或系统输入分支。

「修改账单内容（内部）」仅为两个入口共用的隐藏输入处理，不能作为用户需要添加的第三个动作。原项目预制截图快捷指令依赖的后台自动动作保持隐藏兼容，不恢复为可添加入口，也不改动原项目的导入页面。图文菜单、识别、保存及必要的内部状态处理保留。本次只清理实验入口，**不是重新实现或已解决全部输入问题**。

## 安装与生效范围

本次为 `main` 源码清理，提交使用 `[skip ci]`；没有编译、发布或产生新 IPA。用户已安装的 3.9.0 Build 21 不会因此改变。后续获授权构建并安装新版后，才可在系统动作列表验证清理结果。IPA 仍需用户自行签名。

升级不会自动删除 iPhone 上用户自己创建的快捷指令。引用已移除动作的旧指令将失效，可自行删除；新建只使用上面的两个入口。App 里的普通手动记账、历史账单、预算、标签、分类规则和提交凭证不删除。数据库保持 v35，已成功入账的拆分数据及会话记录保留，不降级或删表。

## 先配置 App

1. 启动 App，创建个人账本、同币种账户，以及需要的分类和标签。
2. 我的 → 智能记账 → iOS 快捷确认记账：设置默认标签、支出预算标记及个人分类规则。动作的账本留空时使用当前账本。
3. 在现有 AI 设置配置文字／视觉服务；图片记账需要视觉能力，文字记账需要文字能力。不要把密钥写入快捷指令。

图片输入交给视觉服务，本机 OCR 只补充分类规则和账户线索；文字动作只发送文字，不发送附带图片。服务商可能计费。识别失败可以选择人工填写当前草稿或取消；这不是独立的自定义收支动作。

## 两个动作的参数

| 参数 | 作用 |
|---|---|
| 图片／文字 | 对应入口的识别输入 |
| 账本 | 可选；留空使用当前账本，不静默选择第一个账本 |
| 标签／清空标签 | 可选；留空跟随 App 默认，明确清空优先 |
| 不计预算 | 仅支出有效；留空跟随 App 默认 |
| 附带图片 | 可选；与识别输入独立，想保留截图需另接同一截图变量 |

附件仅在最终确认保存时处理，遵循 App 的「附件保存原图」设置；文字动作的附件不发送给文字 AI。单图上限 40 MB。取消不创建正式附件关联。

## 保留的确认与分类逻辑

识别只生成当前草稿，先核对再保存。确认菜单保留金额、分类、账户、时间、备注、标签、支出预算标记；可切换账本和收支类型。收入不显示预算项，转账须选择不同的转出／转入账户。币种跟随账本，不自动换算。

分类优先顺序：**人工选择 > 已启用个人规则 > 内置关键词 > AI 建议 > 未分类**。个人规则可限定账本、收支类型、商户／备注／原文和包含／完全匹配；目标失效不写入无效分类。图片取字失败时须核对规则结果。转账不匹配收支分类规则。

账户按已有名称、银行和尾号线索唯一匹配；缺失或歧义时须选择，不直接用旧默认账户。时间按设备本地时区展示，无法识别时用当前时间。标签沿用图文菜单的单标签轮换；支出预算点击反转。

图文入口原有「拆分或新增明细」菜单暂时保留：仅编辑当前草稿，合计等于原付款后最终一次确认并原子保存，不是已撤下的逐笔立即保存动作。收入／转账保持单笔；不支持混合账户拆分或跨币种转账。

## 结果与异常

- 成功只表示本机已入账，云端同步是否完成请在 App 查看。
- 同一请求、相同内容重试沿用原凭证，避免重复扣款；同请求改内容会冲突。
- 提交结果不明时，先在「iOS 快捷确认记账 → 最近提交凭证」并结合实际账单核对，不要直接重新识别／换请求重记。查询辅助 App 动作已撤下，后台查询与凭证存储仍保留。
- 分类、账户等引用失效时返回修改，不静默替换；取消最终确认前不提交。
- 分类规则、请求凭证与拆分会话为本机元数据，普通业务备份或换机不保证恢复这些去重信息。
